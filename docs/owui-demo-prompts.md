# 可直接复制的 OWUI 现场演示问题

> 当前录制仅演示鹈鹕骑车，见 [单场景预制演示](pelican-demo.md)。本文保留真实并发和代码修复案例作为技术评审备用。

在真实 Open WebUI 聊天页面选择“协作助手”后使用。每次复制一个代码框里的正文；不要把说明标题一起发送。主案例只用已准备的 `demo-live` 样例，执行前按 [准备与操作说明](owui-live-demo.md) 准备。默认入口：<http://127.0.0.1:13000>。

问题 1、6 用于录制前预检；问题 2 为正式主案例；问题 3 展示证据不足；问题 4 是快速编码备选；问题 5 用于主案例同一对话的结果复盘。没有预先约定成功秒数，耗时以实际执行为准。

## 问题 1｜录制前知识检索预检

先确认知识就绪与真实引用，正式录像可省略。

```text
请委派检索 Agent 查询知识库 DEMO-PARAM-001，只核对 window_size 的类型、上下限、2 的幂要求和 bool 是否允许。附实际文件名与分块引用，说明证据是否足够实现独立的窗口大小校验函数。回答控制在 150 字以内，不创建文件、不委派编码、不调用 Jira。这份资料是虚构演示规范，不是工程标准。
```

## 问题 2｜主案例：两项并行、编码等待资料

知识检索与 Jira 只读查询同时开始；编码只依赖检索结果。

```text
请调用 execute_task_plan 执行下面的任务计划。展示真实任务状态和依赖等待，最后简短汇总原文引用、Jira 查询结果、真实测试与验收记录，以及实际并发峰值。Jira 是独立只读工具，不是第四个 Agent。 调用时将 tool 字段替换成当前已授权工具的真实完整名称；若有连接前缀，按同名工具后缀准确匹配，不猜测名称。

{
  "tasks": [
    {
      "id": "A",
      "title": "检索窗口校验规范",
      "tool": "delegate_retrieval_task",
      "arguments": {
        "question": "查询 DEMO-PARAM-001，核对 window_size 的类型、上下限、2 的幂要求和 bool 是否允许，附原文引用。",
        "context": "虚构演示资料；仅实现窗口大小校验，不实现完整三字段配置。",
        "acceptance": "规则有真实原文依据，并明确报告证据是否 sufficient。"
      },
      "depends_on": []
    },
    {
      "id": "B",
      "title": "查询 Jira 可见项目",
      "tool": "get_jira_create_context",
      "arguments": {"project_key": ""},
      "depends_on": []
    },
    {
      "id": "C",
      "title": "依规范修复窗口校验并验收",
      "tool": "delegate_coding_task",
      "arguments": {
        "task": "根据依赖任务 A 核实的原文规则，修改既有 demo_window_validator.py 中的 validate_window_size(value)。合法输入返回原整数，非法输入抛 ValueError。先读取两个指定文件，不要修改测试文件 test_demo_window_validator.py，保留其全部内容，只修改实现。只处理这两个指定文件，不扫描整个工作区，不安装依赖，不创建网页。测试文件不得修改、删除或跳过。",
        "repo": "demo-live",
        "context": "窗口校验规范须取自依赖任务 A 的真实充分证据。",
        "acceptance": "实现符合原文；不要修改测试文件 test_demo_window_validator.py；原 3 个 unittest 方法及全部子案例保持不变并实际通过。",
        "verification_commands": ["python -m unittest -v test_demo_window_validator"],
        "preview_target": "",
        "read_only": false
      },
      "depends_on": ["A"]
    }
  ]
}

A 与 B 没有依赖；C 只依赖 A。资料不足时停止 C 并说明缺口。B 失败时如实报告，不把 B 当成 C 的前置条件。不创建或修改 Jira 工单，不 commit、不 push、不发布。不猜测执行状态和耗时；如果当前没有 execute_task_plan，明确说明。
```

## 问题 3｜证据不足：停止编码

展示有依据的停止条件，避免把虚构规范解释为真实设备性能。

```text
请委派检索 Agent，仅依据 DEMO-PARAM-001 判断：threshold=0.65 是否能保证任意真实设备的误报率低于 1%？请核对原文。如果没有通用公式、适用条件和实测证据，列出具体缺口并停止，不委派编码、不创建文件、不操作 Jira。回答控制在 150 字以内，附真实原文引用，不编造性能结论。
```

## 问题 4｜快速编码备选：仅修复单函数

跳过本题不需要的检索与外部业务服务；仍执行真实 SDK 和独立验收。使用前重置专用样例。

```text
请委派编码 Agent 修复已经准备好的演示函数。
repo="demo-live"，preview_target=""，verification_commands=["python -m unittest -v test_demo_window_validator"]。

只读取 demo_window_validator.py 和 test_demo_window_validator.py，只修改实现文件。不要修改测试文件 test_demo_window_validator.py，固定测试完整保留、不得删除或跳过。
实现 validate_window_size(value)：只接受非布尔值的整数，范围为 64 到 4096（含边界），且必须是 2 的幂；合法返回原整数，非法抛 ValueError。
只处理这个函数，不扫描整个工作区，不安装依赖，不创建网页，不查询知识库和 Jira。必须进行真实独立验收，失败按实际错误修复。完成后简短报告真实路径、3 个测试方法的运行记录、退出码、验收结论及固定测试是否保持不变。不 commit、不 push、不发布。
```

## 问题 5｜结果复盘：只读，不重复执行

在主案例同一对话中使用，镜头停留在真实状态与结果证据。

```text
请只总结本次对话已经产生的实际执行记录，不修改文件、不重新运行任务：A 和 B 是否实际并发？C 等待哪个依赖？实际并发峰值是多少？编码运行了什么验收命令、多少个测试方法、退出码是多少、是否通过独立验收？用 6 行以内回答。没有记录的项目标注“没有记录”，不要猜测顺序和耗时。
```

## 问题 6｜录制前 Jira 只读预检

先验证授权与外部服务，避免把外部服务连通性问题混入主案例。

```text
请仅调用 get_jira_create_context，project_key=""，读取当前用户可见的真实 Jira 项目。最多列出 3 个项目的名称和 Key，不创建、修改或删除工单，不猜测项目 Key。如果服务不可用、无权限或没有项目，直接报告真实结果，不反复重试，不委派检索或编码。
```

## 应当展示的真实证据

- A、B 的真实运行区间有重叠，计划结果记录实际并发峰值；模型同一轮提出两个工具调用不能单独证明并发。
- C 先等待 A；只有 A 的证据充分时才启动。B 是独立查询，不是 C 的依赖。
- `demo-live` 为预置的专用样例目录；只修改实现，原测试保持不变。
- 固定命令实际运行 3 个测试方法，覆盖 13 个子输入；unittest 的“Ran 3 tests”不是 13 个测试方法。
- 成功来自真实退出码 0、非空测试集合及独立验收通过。SDK 正常结束不等于验收通过。
- 证据不足、权限拒绝或模型失败都应保留真实状态，不把上一次结果当成本次结果。

当前编排器每个计划最多 6 个任务、最多 3 个并发；一个计划最多委派 1 次检索与 1 次编码。不要用“两次检索同时进行”作为本版备用计划。Jira 写入不在该编排器的演示范围内。
