# Jira 确认表单

`jira-confirmation.js` 处理带 `jira_form.version = 1` 的确认事件。表单只通过 DOM
创建控件，支持修改字段、校验必填内容、取消、Escape、焦点恢复、浅色和深色主题。
点击“确认并提交”返回绑定 `request_id` 的最终字段值，后端仍负责鉴权、字段验证、
审批记录及真正写入；取消返回 `false`。

`patch_frontend.py` 只替换固定 Open WebUI v0.11.4 的确认事件分支，其他确认沿用
原生界面。找不到唯一的预期代码或聊天入口时，构建在修改任何文件前失败。
资产由 `lab/Dockerfile.openwebui` 安装。补丁会自动沿模块引用找到聊天模块的所有
上层入口，给这组模块生成带内容摘要的新文件名，同时更新入口加载及预加载引用。
脚本、CSS 和这组模块使用相同摘要，因此普通刷新就能加载新的可编辑弹窗，
无需依赖浏览器清除旧哈希文件的缓存。已经打开的页面需刷新一次以重新加载代码。

原有模块和上一版生成的模块继续保留，已打开的页面仍可完成原来的资源加载。
`assets/jira-review-manifest.json` 记录本版路径映射，确保重复安装幂等；修改表单
资产后重装会生成完整的新模块图，不会把旧版副本误认成待修改的原始模块。
只重写实际模块导入和 Vite 预加载表，不修改其他文本、非相关模块或版权信息。
Svelte 原始 `version.json` 保持字节不变，与未修改的运行时内置版本一致；补丁版本
独立记录在上述 manifest 中，避免新版页面被错误判定为需要再次更新。

独立演示 `demo.html` 不连接 Jira：`?open=1` 打开表单，`?dark=1&open=1` 预览
深色界面，`?test=1` 在真实浏览器中验证编辑、取消、校验、焦点和文本安全行为。

补丁验证：`python -m unittest discover -s frontend -p test_patch_frontend.py`。
